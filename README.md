# Artemis Cosmos Unofficial Patch
Mod for the Artemis Cosmos Spaceship Bridge Simulator game that provides only bugfixes, with no frills.

###  To download the latest version:
1) Go to https://github.com/quaris628/ArtemisCosmosUnofficialPatch/releases/latest
2) Download the "Source Code" zip file.

### To install:

If you are using linux or configured your filesystem to be case-sensitive (if you don't know what this means then you can almost certainly ignore this): Before you install this mod, open your vanilla install's `data/missions/` directory, and check its subfolders' capitalization. If the names contain uppercase letters, then change them to lowercase letters (for example, change "LegendaryMissions" to "legendarymissions"). (Why this is necessary: vanilla issue [#698](https://github.com/artemis-sbs/LegendaryMissions/issues/698) .) There's no need to do this for subfolders of subfolders.

In short, you need to overwrite the vanilla game's files with the mod's files.
In more detail...
1) Unzip the mod files (in windows, right-click the zip file you downloaded, then select "Extract All...")
2) Browse to your Artemis Cosmos folder that contains the game files that you wish to apply this mod to. (If you bought Artemis Cosmos through Steam, you can open this folder by: starting in your Library window, right-click Artemis Cosmos in the list of your games, hover over "Manage", then select "Browse local files".)
3) Optional, but strongly recommended: Create a backup copy of your entire Artemis Cosmos folder.
4) Take the mod files you extracted and copy them into your Artemis Cosmos folder, such that the mod files overwrite the vanilla files. (Copying the sbs_utils and data folders are all that's necessary for the mod to work, but you should also copy at least the license file and maybe the readme file too.)
5) A window should appear that says the destination already has files with the same names. (If this doesn't happen, then something went wrong in step 4.) When this happens, choose to replace the files in the destination.
If installation was successful, then when the game window opens you should see this mod's name and version beside the Cosmos logo.

"Do I need to install this mod for clients, or just the server?" - I recommend installing on both. This is necessary for all of the bugfixes to work. However, installing on just the server and not the clients is fine; it will fix some bugs and be an improvement over everything running vanilla.

### To report bugs, give feedback, etc:

If you believe the bug/feedback/etc is only pertinent to this mod, then create a public issue on github ( https://github.com/quaris628/ArtemisCosmosUnofficialPatch/issues ) or you may privately email me at `quaris314@gmail.com`.
If this is about a crash or other bug you encountered during a specific game session, then uploading the log file(s) for that session might help diagnose the issue. You can find log files inside a /q_logs/ folder inside the folder of the mission you ran (for example, data/missions/legendarymissions/q_logs/). The timestamps in their names are when the mission was initialized (or restarted).

If you believe the bug/feedback/etc is only pertinent to vanilla Artemis Cosmos, then create a github issue here: https://github.com/artemis-sbs/LegendaryMissions/issues

If you are unsure whether the bug/feedback/etc is pertinent to this mod or vanilla, then assume it's pertinent to this mod; I should be able to sort out which is which, and if it's vanilla I'll forward it.

# List of bugs patched:

Crashes:
- Fixed crash when a single-seat craft is destroyed and the dock location that it was launched from has no other craft (vanilla issue [#662](https://github.com/artemis-sbs/LegendaryMissions/issues/662))
- Fixed crashes and many other very serious bugs that are triggered by typing unusual characters into text input boxes, by disallowing typing unusual characters (vanilla issue [#569](https://github.com/artemis-sbs/LegendaryMissions/issues/569)). For some rarely-used text fields (mainly in the gamemaster console), this fix introduces other visual bugs when typing invalid characters. However, since these visual bugs are much tamer (alibet more obvious) and less common, this still seems like a pretty good tradeoff to me.
- Fixed rare crashes and some other bugs triggered by random corruptions in graphics files when they're auto-generated by the game, by providing uncorrupted copies of all of these files (vanilla issues [#422](https://github.com/artemis-sbs/LegendaryMissions/issues/422), [#606](https://github.com/artemis-sbs/LegendaryMissions/issues/606), and [#392](https://github.com/artemis-sbs/LegendaryMissions/issues/392))

- Fixed crashes when player ship is destroyed in the middle of having its beams rotated or refocused by engineering
- Prevent other possible crashes when rotating or refocusing beams in engineering

# List of Non-Bugfix Features:

Logging:
- Log files are created in a /q_logs/ folder inside the folder of the mission being run (for example, data/missions/legendarymissions/q_logs/)
- In the event of a hard server crash, a python stack trace might be logged to its own file
- The main log file includes info about very basic game events and more specific events relevant to changes made by this mod:
  - Game starting and ending
  - Player ship ids, names, and numbers
  - Player ships getting destroyed and respawning
  - Clients connecting and disconnecting
  - Clients opening consoles
    - Plus more details when opening the engineering console, in hopes it helps diagnose engineering client crashes (vanilla issue [#684](https://github.com/artemis-sbs/LegendaryMissions/issues/684)
  - Single-seat craft launching, docking, and stray craft auto-docking
  - Single-seat craft getting destroyed by black holes
  - Upgrades screen opening and refreshing
  - Errors where code treats deleted ships and other objects as if they were not deleted, which can sometimes cause crashes (such as vanilla issues [#662](https://github.com/artemis-sbs/LegendaryMissions/issues/662), [#688](https://github.com/artemis-sbs/LegendaryMissions/issues/688))
- Normal log files older than 24 hours and hard crash log files older than 7 days get deleted whenever the mission they belong to is run
- Logger will not log entries that are below a configurable priority level
  - Priority levels are, from highest to lowest: Critical, Error, Warning, Info, Debug
  - Default is to log Info and above
  - If this is configured to log Debug and above, then every single line of mast code that gets executed will be logged. Be warned, this makes the log file quickly grow to megabytes in size, and it could grow to a gigabyte or two in a long game.
